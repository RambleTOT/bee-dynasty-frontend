## Открытые пункты

### 26. Демо-день Востока на стенде — пересоздать · P0

28.09 в 15:34 на старом коде к нему применили ручное переназначение №10435 → E10 (версия `5c96cb15`). Исходный план `49992cdf` стал `superseded`, и новый код не находит действующий план: `/days` → `plan_state: draft`, `version: 0`. Ленивое создание (п. 18) не срабатывает: день на дату уже есть.

- **Нужно:** новый демо-день Востока на сегодня с часами 12:30 и автопрогоном, старый — в архив.
- **Через API:** `POST /data/load-demo?region_id=east&date=<сегодня>` (сам архивирует прежний демо-день) → `POST /planning/run` → `POST /planning/{id}/apply` → `POST /data/scenarios/{id}/clock {"time": "12:30", "autoplay": true}`.
- **Иначе:** пометить сценарий `7103c610-07b2-45ce-bb9f-0fefa804b8dc` архивным или сменить ему `date` — тогда `ensure_demo_day` создаст новый. Сейчас он архивные сценарии тоже считает, поэтому просто пометить мало.

### 25. После «Применить с нарушением» день падает с `500` · P0

- **Где:** DS-08 «Переназначить», запись оператора, события — всё в дне, где есть визит с нарушением (после `reassign` с `force: true`).
- **Сейчас:** `evaluate.key()` бросает `ValueError: Infeasible route for E…`. Проверено на копии `5c151a3`:
  - `POST /planning/{id}/reassign/check` → `500`;
  - `POST /booking/requests` на этот день → `500`: `_embed_booking_event` → `engine.apply` → `_try_insert_new` → `ev.report`.

  События идут через тот же `engine.apply`. На стенде 28.09 в 17:02 — пять `500` подряд на `reassign/check`.

- **Нужно:** оценивать и отчитываться по маршрутам с допуском нарушений (как `_report_allow_violations`): уже принятое опоздание не должно ломать следующие расчёты. Если посчитать нельзя — `422` с текстом, а не `500`.
- **Фронт пока:** показывает ошибку в окне.

### 24. Переназначение без позиции ставит заявку в начало маршрута · P1

- **Сейчас:** `apply_manual_reassign`: `pos = position if position is not None else 0`, а проверка (`check_reassign`) при `position = null` ищет лучшую вставку. На копии `5c151a3`: заявка встала на позицию 0 перед тремя выполненными и начатыми визитами, время стало 24:24, 25:14, 26:35.
- **Нужно:** при `position = null` брать позицию, которую нашла проверка, и никогда не ставить заявку перед замороженными визитами (`done`, `in_progress`, `en_route`).
- **Фронт:** всегда передаёт `position` — выбранную, иначе ту, что нашла проверка, и не раньше закреплённых точек. Ошибка остаётся для Swagger и прямых вызовов API.
