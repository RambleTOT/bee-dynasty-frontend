# Расхождения спеки и API

Сверка `docs/spec/FRONTEND_SPEC.md` (v2.2) и живой схемы `https://api.bee-dynasty.ru/openapi.json` (`src/api/schema.d.ts`). Пополняется по мере работы; снимки ответов — `docs/api-examples/`.

## 28.09 — этап 01 (каркас), по схеме

| #   | Где                                   | Спека                                                                             | API (схема)                                                                                                                                                                                                                  | Что делаем                                                                                                       |
| --- | ------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 1   | `POST /planning/{id}/extend-resource` | §12 шаг 7: тело `{order_ids, option: 'add_engineer'}`                             | `ExtendResourceRequest.apply: boolean` — поле обязательное                                                                                                                                                                   | в снимке шлём `apply: false` — только расчёт, план не меняется                                                   |
| 2   | Синтетика, §12 шаг 17                 | ручка загрузки ⏳                                                                 | отдельной ручки нет; источники сценариев — `csv \| booking \| demo \| json`                                                                                                                                                  | снимок ищет уже загруженный синтетический сценарий (`source=json`, id `T000`); нет — шаг пропускается с пометкой |
| 3   | Часы дня, §7                          | `GET/POST /data/scenarios/{id}/clock` ⏳                                          | ручек нет; `ScenarioOut.clock` есть                                                                                                                                                                                          | как в спеке: `nowFor(clock)`, запасной путь — §7                                                                 |
| 4   | `RequestIn`                           | обязательные: `id, duration_minutes, window_start, window_end, required_skill`    | в сгенерированном типе обязательны и поля с серверными значениями по умолчанию (`priority_rank`, `min_skill_level`, `gigabit`, `client_window_locked`, `release_time`, `source`) — так `openapi-typescript` читает `default` | тело события собирать своим типом поверх `Partial<Schemas['RequestIn']>`, а не прямым `RequestIn`                |
| 5   | `UserOut`                             | `{id, login, name, role, region_ids, engineer_id?}`                               | `region_ids` необязательное, `role` — `string`                                                                                                                                                                               | `Role` — свой union (`api/types.ts`), незнакомая роль → экран «Нет доступа»                                      |
| 6   | `ApplyEventRequest.type`              | устаревшие `urgent_request`, `request_cancelled`, поле `time` не используем (§15) | в схеме ещё есть                                                                                                                                                                                                             | не используем                                                                                                    |

## 28.09 — оператор (этап G), по схеме и ответам бэка

| #   | Где                      | Спека                                                                     | API                                                                                                                                                                 | Что делаем                                                                                                                                                 |
| --- | ------------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7   | `GET /booking/requests`  | поиск по № или адресу по всем регионам пользователя                       | ищет только в днях из записей оператора (`source = booking`): префикс номера или подстрока адреса, до 20 строк; в схеме — нетипизированный массив, полей ⏳ 9.2 нет | модель — `adapters/booking.ts` (`normalizeSearchItem`), поля 9.2 читаем, только если пришли; заявки CSV-дня поиск оператора не находит                     |
| 8   | `POST /booking/requests` | `planned` / `unassigned` / 202 `recalculating`, `message` ⏳ 9.4          | в схеме только 201 `BookingRequestOut`; «нет подходящего инженера» — тоже 409 `SLOT_TAKEN` (message «Нет подходящего инженера», без `details.slots`)                | тост — по §8.3.11 из статуса, даты и окна; 202 узнаём по `status: 'recalculating'` в теле; на 409 — плашка «Это окно только что заняли…» и перезапрос окон |
| 9   | `/cancel`, `/reschedule` | `message` ⏳ 9.4; у переноса — новые `request_id`, `date`, `window`       | `/cancel` → `{request_id, status: 'cancelled', plan_id}`, `/reschedule` → `{…, status: 'rescheduled'}`, `message` нет                                               | тексты §8.3.11: отмена — по дате заявки, перенос — по новой дате и окну                                                                                    |
| 10  | `BookingCancelIn`        | `{reason, comment?}` ⏳ 9.3                                               | `{reason?: string}`                                                                                                                                                 | «Другое» скрыто, пока `FEATURES.cancelComment = false`                                                                                                     |
| 11  | `GET /booking/slots`     | `district` по адресу ⏳ 9.7                                               | в `BookingSlotsResponse` поля нет                                                                                                                                   | район читаем, если пришёл (справа в поле «Адрес», в сводке и в записи), иначе не показываем и не шлём                                                      |
| 12  | авария оператора         | `POST /events/apply` без `plan_id` и `event_time`, окно ставит бэк ⏳ 9.1 | `RequestIn.window_start` / `window_end` обязательны                                                                                                                 | заглушка из §8.3.9: «сейчас» браузера и 22:00, после 22:00 — 23:59; вкладка «Авария» — только при `FEATURES.emergencyByRegion`                             |
